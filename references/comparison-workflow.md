# 同一数据，多种可比较的图

路由器协调候选方案，实际绘图继续调用已读过原文的现有 Skill 或作者代码。用户说“给我几种样式看看”“这个图哪种表达更好”“适配不同文章”时进入比较模式；普通单图、小改图直接走原有路线。

## 先决定哪些差异值得比较

从科学问题、输入状态、实验单位、重复/配对结构、结果定义及文章位置决定合法图型。已有语言、图型、期刊要求、色板和代码直接继承。默认 4–6 个候选，上限 12 个；这是总预算，不是把所有模板乘所有配色。可以先 2–3 个图型看表达，再把选中图型做 2–3 个样式，节省渲染和审阅时间。

| 输入与表达 | 可以考虑的差异 | 必须保留或解释 |
|---|---|---|
| 已接受估计值及区间 | 区间森林图、参考线连接的区间图、分面组织 | 相同估计/区间、尺度/参考值和行顺序；不重新拟合 |
| 原始分组观测 | 点图与合适摘要、箱线/分布图、分面 | 实验单位、配对关系、样本量；均值 CI 和中位数/IQR 不是同一种统计量 |
| 随时间的测量 | 轨迹/小多图、趋势与区间 | 时间、重复测量结构、缺失规则；不能伪造平滑或不确定性 |
| 特征矩阵 | 共同尺度的 heatmap、分组/聚类布局 | 归一化、聚类、行列排序和色标含义；更改算法是新科学合同 |
| 已完成 GWAS/MR 等结果 | 对应领域图与通用语言兼容模板 | P/FDR、阈值、过滤、效应单位；不触发全套分析 |
| 机制/流程/图示 | 信息层级、方向、排版和图形语汇 | 实体关系、证据强弱；装饰与定量数据图分开处理 |

再从三个轴选择有理由的差异：**表达形式**（如何编码信息）、**版式与字体**（单栏/双栏、密度、分面、留白）、**颜色与视觉编码**（分类/连续/发散、颜色+形状/线型）。仅换色属于样式变体，不能算新图型。期刊灵感只说明视觉方向；实际尺寸、字体、格式以目标期刊当前指南及作者要求为准。

每个候选必须说明：适合回答什么、改了哪一层、为什么值得看、由哪个具体入口负责、助手补什么。一个候选一个绘图负责人；不同候选可由不同技能绘制；整批比较仍只有一个协调者。没有统一的第三方 JSON 绘图 API，不猜参数。

## 冻结、绘制、收集、选取

1. 保存输入快照和 SHA-256；明确 `data_contract`：单位/设计、输入是原始数据还是已接受结果、纳排、排序、数值含义、区间/检验定义、尺度/参考线、分析权限。需要先分析的任务，先取得一次被接受的分析结果，再生成样式变体。
2. 读选中技能和具体模板，确认语言、输入和 `analysis_effect`。名为 recolor 的入口也可能重新调用分析；不因名称而放行。共享物理尺寸、坐标范围、顺序、类别语义映射；故意改变尺度必须解释并另作比较组。
3. 写 brief 后运行 `comparison.py plan`，向真实绘图者传入快照、合同与各候选配置；绘图由项目脚本或现有技能原生完成。生成真实 PNG 预览，保留 SVG/PDF、代码及实际 analysis JSON，不用样例图/色卡冒充。
4. 汇总 results 后 `assemble` 产生离线 gallery 与证据清单，`check` 复核。失败、缺运行时、未审阅、QA fail 要明确区分；未完成返回非零。实际 analysis JSON 必须规范化一致；这种一致性不证明算法或科研推断正确，仍需源代码/数值和视觉审阅。
5. 给作者展示真实图和各自理由、优势及限制。作者可直接回复 ID；代理执行 `select`。浏览器“导出选择请求”只下载请求，不代表已记录；代理/CLI 验证后才写选择历史。保留所有候选。示例测试选择不是作者的真实偏好。
6. 作者确定方向后，沿用选中技能的终检要求精修和导出。选择状态表示待精修，不自动标为投稿就绪，也不悄悄重置未来任务的默认样式。

## 可执行接口

```bash
python "$ROUTER_SKILL/scripts/comparison.py" plan --brief brief.json --outdir comparison-run
# 现有绘图技能读取快照进行真实渲染，产生 results.json
python "$ROUTER_SKILL/scripts/comparison.py" assemble --plan comparison-run/plan.json --results results.json
python "$ROUTER_SKILL/scripts/comparison.py" check --run comparison-run
python "$ROUTER_SKILL/scripts/comparison.py" select --run comparison-run --id intervals-glacier --reason "作者选择：单栏正文更清楚"
# 或使用gallery导出的请求：select --run comparison-run --choice choice.json
```

字段合同与边界见 [next-development-brief.md](next-development-brief.md)。源码为标准库工具，不执行 brief 中的任意命令。每批使用新目录，防止覆盖旧结果。完整可重现示例见 [examples/comparison](../examples/comparison/README.md)。

## 评价与下一轮

先过技术与科学门，再比较读图效率、层级、文字密度、颜色区分、文章位置和作者偏好。不要给一个无依据的“颜值总分”代替作者选择。用户想要更多时，从已观察到的偏好扩展；不把所有未生成模板都说成试过。文献图片可作为注明来源的灵感；不能冒充用户数据的真实候选，也不能从图像擅自推断可重用许可。


## 中断后的选择恢复

完整验证的 `selection-history.jsonl` 是权威记录，`selection.json` 是最新选择的派生副本。如果 journal 已提交而最新副本写入失败，命令明确返回非零与 `selection_committed_latest_stale`，不报告普通成功。`check` 只读说明 latest 缺失/落后；完整历史及候选证据有效时可显式恢复，且不改动既有选择事件：

```bash
python "$ROUTER_SKILL/scripts/comparison.py" repair-latest --run comparison-run
```

历史本身损坏或候选证据被改动时拒绝恢复，不能靠 repair 掩盖证据问题。像素去重规范化支持的 PNG 为实际 RGBA16 样本，避免 RGB/RGBA、调色板或位深包装制造重复候选；不承诺感知近似或颜色管理后的视觉等价。
